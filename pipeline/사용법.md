# pipeline — 원본에서 Safe-farm 스키마까지

```
python pipeline/extract.py         원본 다섯을 돌려 모은다 → out/mid_*.csv
python pipeline/build.py           중간 CSV + 확정표 상수 → 스키마 4종
python pipeline/verify.py          빈칸·범위·제약 검사
```

한글 출력이 깨지면 `PYTHONIOENCODING=utf-8` 을 앞에 붙인다.

## 원본 하나만 다시 뽑기

원본마다 파일이 하나다. 수집 스크립트와 이름을 맞췄다.

```
python pipeline/src_farmwork.py    농작업일정      (원본/농작업일정/farmwork.py 가 받아온 것)
python pipeline/src_disaster.py    재해예방정보
python pipeline/src_week.py        주간농사정보
python pipeline/src_pest.py        병해충발생정보    ⚠ PDF 57개라 3분쯤
python pipeline/src_variety.py     품종정보         ⚠ 첨부 655개라 1분쯤

python pipeline/extract.py --merge          다시 안 돌리고 있는 것만 모은다
python pipeline/extract.py --only 주간농사정보   그것만 다시 돌려 모은다
```

각자 `out/원본별/<이름>/mid_*.csv` 에 쓴다. 중간 결과가 파일로 남으므로
**병해충 3분은 한 번만 내면 된다.** 다른 원본을 고칠 때는 `--merge` 로 모으기만 하면 된다.

```
python pipeline/extract_pest_alert.py   병해충 경보 → out/pest_alert.csv  (따로. 아래 참고)
```

## 0. 세 층으로 나눈다

```
1층  원본별 날 자료      src_*.py  →  out/원본별/<이름>/
       tables.csv        그 원본의 **표 전부**. 자르지 않는다
       texts.csv         **본문 전부**. 줄 단위
       mid_*.csv         그중 우리가 알아본 것 (날 행. 접지 않음)

2층  사실 모으기        extract.py  →  out/
       mid_*.csv         원본을 가로질러 접고 '실린호'·'출처들' 을 센다
       충돌.csv          같은 자리에 값이 갈리는 곳

3층  스키마로 엮기      build.py  →  crops · crop_variants · crop_stages · disaster_rules
       crop_id 로 조인한다
```

### ★ 1층은 버리지 않는다

`mid_*.csv` 는 **우리가 알아본 것만** 담는다. 얼마나 버리고 있었는지 세어봤다.

```
원본            파일     표       표의 행      표 글자
농작업일정        21     172      634      46,788
재해예방정보      69   9,262   34,581   1,334,223
주간농사정보     192  11,533   23,476   1,001,138
병해충발생정보    57   2,349   12,903     413,295
합계           339  23,316   71,594   2,795,444

mid_table.csv 에 담기던 행 1,502  →  71,594 중 2.1%
```

**97.9%를 버리고 있었다.** 그런데 전부 남겨도 표는 280만 자뿐이다. 남기는 게 맞다.

`안읽은것.md` 는 "없다" 와 "안 읽었다" 를 가르려고 쓴 문서인데,
1층이 있으면 그 물음에 **파일로** 답할 수 있다. 낱말을 바꿔 다시 캘 때 원본을 안 열어도 된다.

### 1층 읽는 법 — `split_cells`

`tables.csv` 의 `내용` 은 **되살릴 수 있게** 적었다.

```python
from common import split_cells
격자행 = split_cells(r["내용"])      # [[칸안의줄, …], …]
```

```
칸 사이     " ¦ "
칸 안 줄    "↵"      ← 원문에 한 번도 안 나오는 글자 (1층 4,100만 자에서 0번)
```

⚠ **줄바꿈을 '/' 로 바꾸면 안 된다.** 원문 칸에 '/' 가 원래 들어 있어서
줄바꿈과 '/' 를 둘 다 가진 칸이 1,382개였다. 한계온도표는 **한 칸 안의 줄**로
작물을 나누는 표라 그 칸들이 통째로 깨진다.

⚠ `texts.csv` 의 `본문` 은 **줄 앞 공백을 지우지 않았다.** PDF 배치 글자는
앞 공백이 칸 자리를 나타낸다. `줄번호` 는 `read_doc` 이 낸 글자에서의 자리이고,
빈 줄을 건너뛰므로 번호에 구멍이 생기는 것이 정상이다.

### 1층 검수 — 2026-09-16

원본을 **독립적으로 다시 읽어** 대조했다. 네 원본 전부 통과.

```
파일 빠짐        0 / 339          모든 파일이 표·본문 양쪽에 있다
표 행 차이       0                농작업 634 · 재해예방 34,581 · 주간 23,476 · 병해충 12,903
본문 줄 차이     0                합 444,446줄
표 글자 잃음     0
되살림 어긋남    0 / 58,691행      split_cells 로 원본 격자와 한 칸씩 대조
원본 섞임        0                같은 파일이 두 원본에 나오지 않는다
(파일·표·행) 중복 0
칸수 ≠ 쪼갠 수   0                구분자가 원문과 부딪히지 않는다
mid_table ⊄ tables  0행           중간 결과가 날 자료의 부분집합이다
```

⚠ 읽다 넘어진 파일은 **조용히 사라지지 않는다.** `dump_raw` 가 끝에 세어 알린다.
예전에는 `read_doc` 이 예외를 삼켜 그 파일이 1층에서 통째로 빠져도 알 수 없었다.

### ★ 접는 것은 2층에서만

`src_*.py` 는 접지 않고 날 행을 그대로 쓴다. 같은 표가 여러 원본에 실리기 때문이다.

```
한계온도표    재해예방정보 18개 호  +  주간농사정보 22개 호
```

원본별로 접으면 같은 규칙의 근거 세기(`실린호`)가 18과 22로 갈린다.
`dedup_rule` 은 `extract.py` 에서만 부른다. **이 성질을 깨뜨리지 말 것.**

### ★ '출처들' — 어느 원본이 같은 말을 했나

```
배추 냉해 -8   실린호 26 · 원본수 2 · 출처들 "재해예방정보:18 · 주간농사정보:8"
```

예전에는 `출처파일` 하나만 남아서 재해예방정보 한 파일만 적혀 있었다.
"이 숫자 어디서 났냐" 에 정직하게 답하려면 이 칸이 있어야 한다(CLAUDE.md 설계원칙).

### 충돌.csv

접기는 값이 **같을 때만** 한다. 값이 다르면 두 행이 남는데, 그게 다른 사실인지
어긋난 것인지 표에는 표시가 없다. 같은 (작물·재해종류·생육단계·지표) 에 값이 갈리면 여기 모은다.

⚠ 동해 −6 과 냉해 −8 처럼 **원래 다른 값**인 것도 섞여 있다. 사람이 가려야 한다.

## 0-1. extract_pest_alert.py 만 왜 따로인가

성격이 다르다. `extract.py` 는 작물 마스터를 만든다 — 배포 때 한 번 시딩하고
해마다 한 번 갱신하는 값이다. **병해충 경보는 그해 그 주의 상황**이라 주 1회 다시 받는다.

담기는 곳도 다르다. 확정표 §G 의 스키마 네 종 어디에도 자리가 없다.

⚠ 헷갈리기 쉬운 경계 — **병해충 '온도 조건' 은 `src_pest.py` 가 맡는다.**
흰가루병 15~28℃ 같은 값은 해마다 바뀌지 않는 정적 값이라 `mid_rule` 로 간다.
`extract_pest_alert.py` 가 뽑는 것은 "올해 몇 호에 무엇이 무슨 등급으로 났나" 뿐이다.

## 0-2. extract 와 build 를 가르는 선

### ★ 없으면 비운다

**`extract` 는 못 찾은 값을 짐작해서 채우지 않는다. 빈칸으로 둔다.**

```
원문에 있다   →  값 + 출처파일 + 위치.  build 가 confirmed=Y 로 쓴다
원문에 없다   →  빈칸.                 build 가 논문값을 넣고 confirmed=N 을 붙인다
애매하다     →  값은 담되 종류를 '미분류' 나 '상한후보?' 로.  사람이 본다
```

빈칸이 많은 것은 흠이 아니다. **빈칸이어야 할 자리가 채워져 있는 것이 사고다.**
억지로 채우면 논문에서 온 값이 "원문 근거 있음" 으로 둔갑한다.

지금 `base_temp` 는 본선 작물 중 넷만 원문 근거가 있다(감자·마늘·시금치·수박). 나머지는 비어 있는 게 맞고,
`GDD계산관련/작물_확정표.md` §B-2 가 논문값으로 채운다.

## 1.5 ★ 작물을 더할 때

**`extract.py` 의 `CROPS` 한 곳에만 더한다.** 나머지는 거기서 만들어진다.

```python
CROPS = [
    # 표준이름,  본선,  다른표기,       문서 {cntntsNo: (이름, 본선문서)}
    ("고추",    True,  ["고추(피망)"],  {"30600": ("고추(보통재배)", True)}),
]
WANT, CROP_ALIAS, MAIN_CROPS, CROP_STD = _build_registry()
```

```
표준이름    파이프라인이 쓰는 하나의 이름
본선       True = 제품에 넣을 작물 ('본선' 칸이 Y 가 된다)
          False = 근거 추적용으로만 뽑는다 (딸기·옥수수·쪽파)
다른표기    원문 표·본문에서 만나는 딴 이름. "가루쌀"→벼, "고추(피망)"→고추
문서       농작업일정 cntntsNo. 원본/농작업일정/raw/lst_*.xml 에 있다. 짐작하지 말 것
```

### 순서

```
① lst_*.xml 에서 cntntsNo 를 찾아 CROPS 에 한 줄 더한다
② 돌린다. 아래 경고가 뜨면 고친다
③ 재해예방정보 표에 딴 이름으로 적혀 있으면 '다른표기' 에 더한다
```

### 틀리면 알려준다 — 조용히 빠지지 않는다

```
⚠ 등록했는데 원본 lst_*.xml 에 없는 작물        cntntsNo 가 틀렸거나 아직 안 받았다
⚠ 등록표 이름과 원본 이름이 다릅니다             원본 쪽을 별칭에 자동으로 잇는다
⚠ 첨부 파일이 없는 작물                       raw 만으로는 온도·적산온도가 안 나온다
⚠ 저온해 에 'OO' 이(가) 있습니다               건너뛰던 계열에 등록 작물이 생겼다 → 읽는다
ValueError: 작물 이름이 겹칩니다                두 작물이 같은 이름을 주장한다
```

⚠ **등록 안 된 작물은 원문 이름 그대로 남는다.** `'샐 러 리'` 와 `'샐러리'` 가 따로 센다.
등록하면 표준명으로 합쳐진다. 지금 그런 것 — 오이·호박·참외·쑥갓·샐러리·온실멜론·과수.

⚠ **작물 수를 글에 적지 않는다.** 예전에 `'14작물'` 이라는 칸 이름과 말이 20개 파일에
70여 번 박혀 있다가, 작물을 줄이자 한꺼번에 전부 틀린 말이 됐다.
칸 이름은 `'본선'` 이고, 값은 `MAIN_CROPS`(등록표의 '본선')가 정한다.

```bash
python pipeline/crops.py       지금 등록된 작물·문서·본선 여부
```

## 1.6 작물을 하나 되살릴 때

`add_crop.py` 가 보관에서 옮겨주고 등록표에 붙일 줄을 만들어 준다.

```bash
python pipeline/add_crop.py --list          보관에 있는 176작물
python pipeline/add_crop.py --list 상추      이름에 '상추' 가 든 것만
python pipeline/add_crop.py 오이 --dry       옮기지 않고 무엇을 할지만
python pipeline/add_crop.py 오이 호박         실제로 옮기기
```

⚠ **176개를 한꺼번에 받는 도구가 아니다.** 21작물만 두는 것은 의도한 것이고,
필요할 때 하나씩 더하는 데 쓴다.

### 왜 두 단계인가

```
① 원본 옮기기    보관/농작업일정/결과/  →  원본/농작업일정/
                 erajson · dtl · era · 첨부 hwpx  네 파일
② 등록표에 한 줄  pipeline/crops.py 의 CROPS
```

**둘 다 해야 한다.** 등록만 하면 `crop_map()` 이 "원본에 없다" 고 경고하고,
원본만 옮기면 아예 안 읽힌다. ①은 스크립트가 하고, ②는 만들어준 줄을 붙여넣으면 된다.

⚠ **표준이름과 `본선` 은 사람이 정한다.** 스크립트가 만든 줄은 초안이다.
같은 작물의 다른 작형이면 새 줄을 만들지 말고 **기존 줄의 문서 칸에 넣는다.**

```python
("무", True, [], {"30614": ("무", True),
                  "30615": ("무(고랭지재배)", True)}),
```

### 그 다음

```bash
python pipeline/src_farmwork.py      농작업일정만 다시 뽑기
python pipeline/extract.py --merge   모으기
```

⚠ 재해예방정보·주간농사정보·병해충발생정보는 **문서 하나에 작물 수십 개가 섞여 있어**
다시 안 돌려도 된다. 그쪽은 읽으면서 등록 작물을 거르므로,
새 작물의 재해 규칙까지 받으려면 `python pipeline/extract.py` 로 전체를 돌린다.

## 2. ★ mid_temp.csv 의 `종류` 칸

**이 칸이 이 파이프라인에서 가장 중요하다.** 온도를 한 표에 담되 섞이지 않게 가른다.

```
종류         뜻                                   어디로
─────────────────────────────────────────────────────────────────
적온         가장 잘 자라는 온도                     ❌ 아무 데도 안 씀
하한후보      "이 온도 이상에서 자라기 시작"            crops.base_temp 후보
상한후보      "이 온도 이상에서는 생육 정지"            crops.upper_temp 후보
한계_최저      표의 '최저 한계' 칸                    ⚠ 참고만. 경보 아님
한계_최고      표의 '최고 한계' 칸                    참고
동해 · 냉해    "이 아래로 가면 얼어 죽는다/냉해"         disaster_rules
단계별저온     모기를 때 / 꽃눈생기기전 / 꽃필 때        disaster_rules
고온해        등급(주의/위험)이 붙은 고온 기준           disaster_rules
```

### 방향 판정 규칙

**`이상` 이 붙었다고 하한이 아니다. 뒤에 오는 말이 뜻을 뒤집는다.**

```
"5℃ 이상에서 자라기 시작함"      → 하한후보
"25℃ 이상에서는 생육 정지"       → 상한후보
"25℃ 이상 더위에 약하다"         → 상한후보
"12℃ 이하 저온에 감응하여 추대"   → 단계별저온 (추대 경보)
```

둘을 묶었다가 마늘·양파·시금치의 고온 상한 25℃ 가 `base_temp` 후보로 올라온 적이 있다.

### 적온을 버리지 않고 담는 이유

`재배적 특성표` 의 `생육온도` 행은 **전부 적온**이다(발아적온·개화적온·생육적온·결구적온·
저장적온·야간적온). 계산에 쓰면 안 되지만, **버리면 다음 사람이 또 캔다.**
`종류=적온` 으로 담아두고 `build.py` 가 무시한다.

#### 생육시기 — 세 방법을 다 쓴다

문장형만 보면 출수기 137 · 성숙기 1 밖에 못 잡는다. 셋을 다 쓰면 크게 는다.
어떻게 찾았는지를 `시기근거` 칸에 같이 적는다 — 숫자만 믿지 말라는 뜻이다.

```

```

평문 hwp 가 이렇게 나온다. 머리블록은 이 규칙을 쓴다.

```
품 종 명        ← 머리 블록 시작
출수기
(월. 일)        ← 단위 표시. 여기가 머리 블록이라는 증거
벼 키
(㎝)
진한           ← 값 블록. 요약서의 주인공 품종이 첫 줄에 온다
```

⚠ **그 시기를 말하는 문장인지 봐야 한다.**
`"출수기가 늦으므로 6월 10일 이내에 모내기를 완료"` 를 출수기로 읽으면 벼 출수기가
6월이 된다. 모내기·이앙·완료 같은 말이 들어간 줄은 건너뛴다.
