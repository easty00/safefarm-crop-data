# 주간농사정보 수집 — 사용법

## 이 폴더는 뭐야?

농사로 **주간농사정보(`weekFarmInfo`)** 하나만 맡는 폴더야.

```
주간농사정보/
  week.py        ← 실행할 프로그램 (이거 하나면 돼)
  사용법.md       ← 지금 읽고 있는 것
  결과/
    raw/         농사로가 보내준 원문 (이미 2개 들어있음)
    첨부/         내려받은 문서 (연도로 폴더가 갈려)
    본문/         문서를 글자로 바꾼 txt  ← 내가 읽을 건 여기야
    목록.csv      870건 전부  ← 이미 만들어뒀어
```

`.env` 는 이 폴더에 안 넣었어. 프로그램이 **위쪽 폴더로 올라가면서 찾아** 써.

## 이 서비스의 규모

```
870건 · 2010년 ~ 2026년 9월 · 주 1회 (연 51~54건)
```

| 연도 | 건수 | | 연도 | 건수 |
|---|---|---|---|---|
| 2026 | 36 | | 2022 | 52 |
| 2025 | 51 | | 2021 | 52 |
| 2024 | 53 | | 2020 | 52 |
| 2023 | 52 | | 2010~2019 | 각 51~54 |

**이번에 받는 건 2023~2026년 192건**이야. 재해예방정보와 같은 범위로 맞췄어.

목록 870건은 **연도와 상관없이 전부 `목록.csv` 에 남아.** 첨부만 연도로 골라 받는 거야.
나중에 `--year` 로 다른 해를 채워도 이미 받은 건 안 겹쳐.

## 첨부가 세 판본으로 와

한 건에 같은 내용의 **hwp / hwpx / pdf** 가 최대 3개씩 붙어 있어.

```
판본 1개  339건
판본 2개   37건
판본 3개  124건
형식 분포  hwp 738 · hwpx 246 · pdf 162 · zip 1
```

**기본은 하나만 받아.** 셋 다 받으면 용량이 세 배가 되는데 내용이 같거든.
고르는 순서는 `hwpx → hwp → pdf → zip` 이야. 글자가 깨끗한 순서야.

다만 **목록에는 판본 이름이 전부 남아** (`판본` 칸). 뭐가 있었는지는 안 잃어버려.
셋 다 받고 싶으면 `--files all` 을 쓰면 돼.

### 여기 함정이 하나 있어

`fileName` 과 `downUrlList` 가 둘 다 `|` 로 이어진 목록이야.

```
fileName     "…제37호.hwpx|…제37호.hwp|…제37호.pdf"
downUrlList  "…ep=A|…ep=B|…ep=C"
```

**나누지 않고 통째로 쓰면 이름과 주소가 어긋나.** `.pdf` 라는 이름의 파일에 hwpx
알맹이가 담기고, 판독이 전부 실패해. 전에 실제로 그렇게 됐던 적이 있어서 짝을
맞춰 쓰도록 해뒀어. 그리고 저장한 뒤에도 **앞 4바이트로 형식을 다시 확인해.**

## 실행 방법

```
cd "C:\Users\lecra\Desktop\safe\api테스트\주간농사정보"
python week.py
```

기본이 **2023~2026년 192건 · 판본 하나씩**이야. 40분~1시간, **1.2GB** 정도 될 거야.

### 목록만 (1분)

```
python week.py --files none
```

이미 한 번 돌려놔서 `raw/` 에 응답이 들어있어. 다시 실행하면 API 를 안 부르고
`목록.csv` 와 `요약.md` 만 새로 만들어.

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--year 2023,2024,2025,2026` | **기본값.** 쉼표로 여러 해 |
| `--year 2010,2011,2012` | 옛날 것을 채울 때 |
| `--files one` | **기본값.** 판본 하나씩 |
| `--files all` | 판본 전부. 용량 세 배 |
| `--files none` | 첨부 안 받음. 목록만 |

## 결과물

```
결과/
  요약.md      ★ 이걸 나한테 보여주면 돼
  대조.md      ★ 이것도. 연도끼리 맞대본 결과
  목록.csv     870건 전부 + 응답 칸 전부
  목차.csv     문서마다 항목 제목을 뽑아놓은 것
  본문/        전문 txt  ← 내가 직접 읽을 것
  첨부/        원본 hwpx·hwp·pdf
```

### 목록.csv

응답 칸을 하나도 안 버리고 다 넣고, 읽기 쉬운 칸을 더 붙였어.

```
cntntsNo, subject, writerNm, regDt, hitCt, downUrl, downUrlList, fileName, fileSeCode  ← 응답 원본
연도, 호수, 기간, 판본수, 판본, 고른파일, 첨부, 첨부KB, 본문, 본문자수, 쪽수          ← 붙인 것
```

`호수` 와 `기간` 은 제목에서 뽑았어. `주간농사정보 제 37호 (2026.9.14.~9.20.)` →
호수 `37`, 기간 `2026.9.14.~9.20.` 이야. **호수가 연도 대조의 열쇠야.**

### 대조.md — 이게 이번 핵심 질문이야

주간농사정보는 **매년 같은 주차에 같은 농작업**을 안내할 가능성이 높아.
2023년 제20호와 2025년 제20호가 거의 같은 내용이면, 우리는 **한 해만 쓰면 돼.**

그래서 대조를 이렇게 해.

1. **항목 제목이 연도끼리 얼마나 겹치나** — 겹치는 비율이 높으면 매년 재수록이라는 뜻
2. **같은 호수끼리 글자 수** — 제20호를 4년치 나란히. 분량이 확 바뀌었으면 개정된 거야
3. **한쪽 연도에만 있는 항목** — 새 품종·새 병해충이 여기 걸려

재해예방정보 때는 표 제목으로 대조했는데 **띄어쓰기와 한자 표기가 달라서 같은 표가
다른 표로 세어졌어.** 이번엔 항목 제목을 띄어쓰기 정리해서 쓰지만, 그래도 완벽하진
않아. 숫자는 참고만 하고 **판정은 내가 본문을 읽고 할게.**

## 솔직하게 — 이게 쓸모 있을지는 아직 몰라

우리는 이미 **농작업일정 176건**에 작물별 작업 시기를 순(旬) 단위로 갖고 있어.
주간농사정보가 그보다 나은 걸 주는지는 **실제로 읽어봐야** 알아.

그래서 17년치를 다 받지 않고 4년치만 받는 거야. 읽어보고 값어치가 있으면
`--year` 로 나머지를 채우고, 없으면 여기서 멈추면 돼.

## 중간에 끊기면?

**그냥 다시 실행하면 돼.** 이미 받은 첨부와 이미 만든 txt 는 건너뛰어.
0바이트로 저장된 파일은 지우고 다시 받게 해뒀어. 오류 응답은 저장 안 해.

## 다 받은 다음에 할 일

`결과/요약.md` 와 `결과/대조.md` 를 보여줘. 내가 볼 건 이 네 가지야.

1. **판독 실패가 몇 건인가** — 특히 옛날 `.hwp` 가 잘 읽히는지
2. **연도끼리 겹치는 항목 비율** — 이게 이번 판단의 핵심이야
3. **자주 나오는 항목 상위 50** — 작물 이름이 고르게 보이는지. 벼만 잔뜩이면 값어치가 낮아
4. **본문 분량 중앙값** — 1,000자 미만이 많으면 알맹이가 없다는 뜻

## 문제가 생기면

- `.env 를 찾지 못했습니다` → 위쪽 폴더(`api테스트`)에 `.env` 가 있는지 확인
- `resultCode 13` → 오퍼레이션 이름 문제. 매뉴얼 이름만 썼으니 나오면 알려줘
- `hwpx 가 아니라 그냥 압축파일입니다` → `.zip` 첨부가 1건 있어. 그건 이 메시지가 맞아
- `모르는 형식 (앞 4바이트 …)` → 확장자 대신 내용으로 판정하는데도 모르는 게 나온 거야

## 참고 — 왜 천천히 받나

다른 스크립트들과 같은 간격이야.
