# 농작업일정 수집 — 사용법

## 이 폴더는 뭐야?

농사로 **농작업일정정보(`farmWorkingPlanNew`)** 하나만 맡는 폴더야.
서비스 하나를 끝까지 파는 게 목표라, 관련된 게 전부 여기 들어있어.

```
농작업일정/
  farmwork.py     ← 실행할 프로그램 (이거 하나면 돼)
  사용법.md        ← 지금 읽고 있는 것
  결과/
    raw/          농사로가 보내준 원문 (이미 22개 들어있음)
    첨부/          내려받은 파일 (이미 3건 들어있음)
```

`결과/raw` 와 `결과/첨부` 에 **전에 받아둔 게 이미 들어있어.** 그래서 다시 실행해도
그만큼은 안 받고 넘어가.

`.env` 는 이 폴더에 안 넣었어. 프로그램이 **위쪽 폴더로 올라가면서 찾아** 쓰거든.
키 파일을 여러 곳에 복사해두면 나중에 어느 게 진짜인지 헷갈리니까 원본 하나만 두는 게 나아.

## 방침 — 일단 다 받는다

**버리는 판단은 내용을 본 다음에 한다.** 그래서 이 프로그램은 기본값으로 전부 받아.

- 응답으로 오는 **칸을 하나도 안 버려.** 안 쓸 것 같은 코드값도 CSV 에 다 들어가
- 첨부파일도 **기본값이 전부**야 (약 250MB)
- 재배법에서 **제목 없이 앞에 붙은 내용도 `(머리말)` 로 남겨**
- 달력의 라벨 같은 칸도 지우지 않고 **`라벨로보임` 칸에 표시만** 해둬

딱 하나 예외가 **외국인근로자 번역본 6건**이야. 같은 농작업일정을 라오어·몽골어·베트남어·
영어·크메르어·태국어로 옮긴 것이라 새로운 작물 데이터가 없어서 어느 모드에서도 안 받아.
다만 **목록(`작물목록.csv`)에는 그대로 남아** 있어.

## 이 서비스가 주는 것

오퍼레이션이 5개야. 이 프로그램은 5개를 다 쓰고, 5개 다 CSV 로 뽑아.

| 오퍼레이션 | 응답 칸 | 나오는 파일 |
|---|---|---|
| `workScheduleGrpList` | 3 | `작물목록.csv` |
| `workScheduleLst` | 6 | `작물목록.csv` |
| **`workScheduleEraInfoJsonLst`** | **13** | **`농작업시기.csv`** ★ |
| `workScheduleDtl` | 5 | `재배법.csv` |
| `workScheduleEraInfoLst` | 1 | `달력.csv` |

**핵심은 세 번째야.** 다섯 번째(HTML 달력)는 36칸을 세어야 시기를 알 수 있는데,
세 번째는 `시작월·시작순·종료월·종료순`을 숫자로 바로 줘.

다섯 번째도 풀어서 CSV 로 뽑는 건 **두 값이 어긋나는지 자동으로 대조하려고**야.
`요약.md` 에 어긋난 건수가 나와.

## 실행 방법

명령 프롬프트를 열고 이 폴더로 이동해:

```
cd "C:\Users\lecra\Desktop\safe\api테스트\농작업일정"
```

### 1) 먼저 10건만 (추천)

```
python farmwork.py --limit 10
```

3~5분. 잘 돌아가는지, 결과 모양이 쓸 만한지 확인하는 게 목적이야.

### 2) 잘 되면 전체

```
python farmwork.py
```

**20~40분, 약 250MB.** 첨부를 다 받기 때문이야.

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--limit 10` | 앞에서 10건만. 시험용 |
| `--files all` | **기본값.** 첨부 전부 (외국인근로자 번역본만 제외) |
| `--files pick` | 전략작물 가이드북 PDF 7건 + 구형 hwp 3건만. 약 60MB |
| `--files none` | 첨부 안 받음. API 만. 제일 빠름 |
| `--no-detail` | 재배법 건너뛰기 |

### 첨부파일 구성

176건의 첨부는 이렇게 갈려.

```
"○○ 농작업일정.hwpx"        160건   약 190MB
"전략작물 가이드북(○○).pdf"    7건   API 에 없는 내용이 8~10쪽 더 있음
"외국인근로자 … 번역본.pdf"     6건   번역본 — 항상 제외
".hwp" (완두·사과·국화)         3건   구형식
```

hwpx 160건은 벼 한 건에서 API 재배법과 94.8% 겹쳤어. 그런데 **표본 1건이라 일반화할 수 없어서**
기본값에서 빼지 않았어. 다 받아보고 채소·과수도 겹치는지 확인한 뒤에 버릴지 정하자.

## 결과물

```
결과/
  요약.md        ★ 이걸 나한테 보여주면 돼
  농작업시기.csv   ★ 작물 × 작업 × 시기.  crop_schedules 의 초안
  달력.csv        HTML 달력을 칸 단위로 푼 것 (위와 대조용)
  재배법.csv      작물 × 섹션 × 내용
  작물목록.csv     176건 목록 + 첨부 링크
  raw/           원문
  첨부/           분류별 폴더로 나뉜 첨부파일
```

### 농작업시기.csv — 이게 제일 중요해

한 줄이 "어떤 작물의 어떤 작업이 언제부터 언제까지인지" 하나야.
176건이면 **2,000~3,000줄** 나올 거야.

```
분류명, 작물명, cntntsNo, 품목코드, 품목명, 작업구분,
정보구분코드, 정보구분, 작업명,
시작월, 시작순, 종료월, 종료순, 소요순수, 동영상,      ← 여기까지가 응답 13칸 전부
시작순번, 종료순번, 지속순수, 시작중앙일, 종료중앙일     ← 프로그램이 계산해 넣은 것
```

계산해 넣은 네 칸은 이런 뜻이야.

```
순번        '4월 상순' → 9        1월 상순이 0, 12월 하순이 35
중앙일       '4월 상순' → 04-05    상순 5일 · 중순 15일 · 하순 25일
```

순번은 정렬하고 기간을 재는 데 쓰고, **중앙일은 나중에 기상 데이터를 붙일 때** 써.

`정보구분` 은 세 가지로 갈려.

```
생육과정(주요농작업)        유묘기 · 이식기 · 개화기 · 수확 …
기상재해 및 예상되는 문제점   가뭄 · 장마 · 폭염 + 그때 생기는 문제
병충해 방제                방제 시기
```

### 달력.csv — 대조용

HTML 달력은 항상 **36열**(12개월 × 상·중·하순)이야. 칸 너비(`colspan`)를 더해가며
위치를 세면 시기가 나와. 그걸 한 줄씩 풀어놨어.

```
분류명, 작물명, cntntsNo, 섹션, 행,
시작순번, 종료순번, 지속순수, 시작월, 시작순, 종료월, 종료순,
내용, 색상, 라벨로보임
```

**`라벨로보임` 칸을 눈여겨봐.** 기상재해 표에는 `가뭄 →` 처럼 앞쪽 빈 달을 빌려
행 이름을 적어둔 칸이 있어. 시기로 읽으면 1월 상순부터라고 잘못 나와.
지우지 않고 `Y` 로 표시만 해뒀으니, 진짜 라벨인지 판단은 나중에 하자.

### 재배법.csv

HTML 을 제목 기준으로 잘라 섹션별로 한 줄씩 넣었어. 통째로 두면 값을 못 찾거든.
벼로 확인해보니 **11개 섹션**이 나오고, `벼베기 적기` 섹션 안에 이게 들어있어.

```
벼베기 적기 (출수 후 적산온도가 1,100∼1,200℃ 되는 시기)
지역 | 조생종 | 중생종 | 중만생종 | 중부 | 50일 | 53일 | 57일 | 호남 | 52일 | 55일 | 60일 …
```

표는 칸 경계를 `|` 로 살려뒀어. 지우면 숫자가 한 덩어리로 붙어서 못 읽거든.

## 중간에 끊기면?

**그냥 다시 실행하면 돼.** 이미 받은 건 건너뛰고 이어서 받아.

오류 응답은 저장하지 않게 해뒀어. 농사로가 "그런 건 없다"고 답한 걸 정상인 줄 알고
저장해두면 다음에 건너뛰어서 영영 모르게 되거든.

## 다 받은 다음에 할 일

`결과/요약.md` 를 보여줘. 내가 볼 건 이 다섯 가지야.

1. **JSON 과 달력이 어긋난 건수** — 0이면 두 방식이 같은 답을 주는 거야.
   0이 아니면 어느 쪽이 맞는지 원문을 봐야 해
2. **순 번호 변환 실패가 0건인가** — 0이어야 정상
3. **작업구분(`farmWorkFlag`)에 무슨 값이 들어있나** — 이게 제일 궁금해.
   전에 논농사 5건으로 봤을 땐 `벼 직파재배`·`벼 기계이앙재배`처럼 **작물명**이 나왔어.
   채소에서 `촉성`·`반촉성` 같은 게 나오면 **시설재배를 걸러낼 수 있어**
4. **시기 정보가 0건인 작물이 몇 종인가** — 많으면 그 작물들은 이 API 로 못 써
5. **재배법에 `(머리말)` 만 나온 작물이 몇 종인가** — 많으면 제목 태그가 작물마다
   다르다는 뜻이라 분할 방법을 고쳐야 해

## 문제가 생기면

- `.env 를 찾지 못했습니다` → 위쪽 폴더(`api테스트`)에 `.env` 가 있는지 확인
- `resultCode 13` → 오퍼레이션 이름 문제. 매뉴얼에 적힌 이름만 썼으니 나오면 알려줘
- `resultCode 11` → 인증키 문제
- 시기 정보가 대부분 0건으로 나오면 → 이 오퍼레이션이 일부 작물에만 열려 있다는 뜻이야.
  그러면 달력.csv 를 주력으로 바꿔야 해. 꼭 알려줘
- 용량이 부담되면 `--files pick` 으로 줄여도 돼. 나중에 `--files all` 로 다시 돌리면
  빠진 것만 채워 받아

## 참고 — 왜 천천히 받나

요청 사이에 0.4초씩 쉬도록 해뒀어. 농사로는 정부 서버라 짧은 시간에 몰아서 요청하면
차단될 수 있거든. 다른 프로그램들과 같은 간격이야.
