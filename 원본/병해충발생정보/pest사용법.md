# 병해충발생정보 수집 — 사용법

## 이 폴더는 뭐야?

농사로 **병해충발생정보(`dbyhsCccrrncInfo`)** 하나만 맡는 폴더야.

```
병해충발생정보/
  pest.py        ← 실행할 프로그램 (이거 하나면 돼)
  사용법.md       ← 지금 읽고 있는 것
  결과/
    raw/         농사로가 보내준 원문
    파일/         내려받은 PDF (연도로 폴더가 갈려)
    본문/         PDF 를 글자로 바꾼 txt  ← 내가 읽을 건 여기야
```

`.env` 는 이 폴더에 안 넣었어. 프로그램이 **위쪽 폴더로 올라가면서 찾아** 써.

## 규모

```
257건 · 2010년 ~ 2026년 · 월 1~2회 (연 12~18건)
첨부는 전부 PDF, 건당 7~8MB · 40~50쪽
```

**이번에 받는 건 2023~2026년 57건 (약 430MB).** 다른 자료와 범위를 맞췄어.
40분 안에 끝나. 지금까지 받은 것 중 제일 가벼워.

## ⚠ 매뉴얼에 없는 함정 — `numOfRows`

매뉴얼에 페이징 변수가 안 적혀 있어. 그런데 **실제로는 먹어.**

```
안 주면            10건만 옴   ← totalCount 는 18이라고 나오는데 10건만 온다
numOfRows=100      18건 다 옴
```

**이걸 모르면 연 15~18건인 해에서 조용히 잘려.** 오류도 안 나고 그냥 적게 와.
그래서 `ROWS = 100` 으로 넉넉히 주고, 받은 수가 `totalCount` 보다 적으면 경고를 찍게 해뒀어.

그리고 연도 목록에 **`전체`** 라는 값이 끼어 있는데 그걸로 조회하면 **0건**이 와.
숫자인 연도만 골라 쓰도록 했어.

## 이 자료가 왜 특별한가 — 이미 표로 갈려 있어

지금까지 받은 자료는 전부 서술문에서 숫자를 캐내야 했는데, 이건 **첫 쪽에 요약표가 있어.**

```
Ⅰ. 식량작물
▶ (경    보) 해충: 벼멸구, 혹명나방
▶ (주 의 보) 병 : 이삭도열병, 세균벼알마름병, 깨씨무늬병
▶ (예     보) 병 : 잎집무늬마름병, 흰잎마름병
```

**작물군 · 경보등급 · 병/해충 구분 · 이름**이 이미 나뉘어 있어. 그대로 표로 옮길 수 있어.
등급 글자 사이에 공백이 들어가 있어서(`주 의 보`) 공백을 지우고 맞춰. 원문도 같이 남겨둬.

본문은 이렇게 생겼어.

```
4  세균벼알마름병  <주의보>
❍ 특히, 발병 최적 온도는 30 ~ 35℃(최저 10, 최고 43℃), 습도 90% 이상
```

**발병 조건 온도가 숫자로 적혀 있어.** 이건 `disaster_rules.csv` 에 바로 들어갈 재료야.

샘플 3건으로 시험해보니 호당 요약 18~21행, 본문 항목 28~31개, 온도 문장 4~10개가 나와.

추출기를 가져와야 합니다" 라고 알려줘. 그때 옮겨 붙이면 돼.

## 결과물

```
결과/
  요약.md      ★ 이걸 나한테 보여주면 돼
  대조.md      ★ 이것도. 연도끼리 맞대본 결과
  목록.csv     응답 칸 전부
  경보.csv     ★ 작물군 × 등급 × 병/해충 × 이름   ← 제일 쓸모 있을 것
  항목.csv     본문 항목 + 발병 조건 온도 문장
  본문/        전문 txt
  파일/        원본 PDF
```

### 경보.csv

```
연도, 호수, 기간, 작물군, 등급, 구분, 병해충명, 원문
```

한 줄이 "몇 년 몇 호에 어느 작물군의 무슨 병해충이 어느 등급으로 났는지" 하나야.
`원문` 칸에 잘라내기 전 줄을 그대로 남겨뒀어. 잘못 갈렸는지 확인하려고.

### 항목.csv

```
연도, 호수, 기간, 번호, 병해충명, 등급, 본문줄수, 온도문장수, 온도문장
```

**`온도문장수` 가 0보다 큰 줄이 우리가 찾는 거야.** 여기서 발병 조건을 추려서
`disaster_rules.csv` 로 옮길 거야.

항목 본문은 **다음 항목이 시작하는 줄에서 정확히 끊어.** 줄 수로 대충 끊었더니
다음 항목의 온도를 끌어와서 이삭도열병에 잎집무늬마름병 온도가 붙었던 적이 있어.

### 대조.md

병해충은 다른 자료와 대조 방식이 달라야 해. **같은 달에 같은 병해충이 반복되는지**가
핵심이거든. 반복되면 그건 달력으로 쓸 수 있는 상시 경계 대상이야.

1. **호수 × 연도 격자** — 몇 호에 몇 건이 실렸나
2. **해마다 되풀이되는 병해충** — 나온 연도 수로 정렬. 4년 다 나오면 상시 대상
3. **한 해에만 나온 병해충** — 새로 나타났거나 그해만 문제였던 것. 여기가 진짜 변화

## 다 받은 다음에 할 일

`결과/요약.md` 와 `결과/대조.md` 를 보여줘. 내가 볼 건 이 네 가지야.

1. **판독 실패가 몇 건인가** — 옛날 호가 hwp 면 여기 걸려
2. **경보.csv 행 수가 호당 15~25행쯤 되나** — 너무 적으면 요약표 모양이 해마다 다른 거야
3. **작물군이 제대로 갈렸나** — `(못 읽음)` 이 많으면 로마숫자 머리를 못 잡은 거야
4. **온도 문장이 있는 항목이 몇 개인가** — 이게 `disaster_rules` 재료의 양이야

## 문제가 생기면

- `.env 를 찾지 못했습니다` → 위쪽 폴더(`api테스트`)에 `.env` 가 있는지 확인
- `ROWS 를 늘리세요` 경고 → 받은 수가 totalCount 보다 적다는 뜻. 알려줘
- `hwpx 입니다 / hwp 입니다` → 옛날 호 형식. 추출기를 옮겨 붙이면 돼
- 경보.csv 가 비어 있으면 → 요약표 모양이 바뀐 거야. 본문 txt 첫 쪽을 보여줘
