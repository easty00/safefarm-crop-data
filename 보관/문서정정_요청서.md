2026-09-15 작성. 대상 폴더: `api테스트/`

## 이 요청서가 나온 배경

작물 데이터 수집·선별이 끝난 뒤, **인계 문서와 실제 산출물을 70개 파일 단위로 대조**했습니다.

결과는 이렇습니다.

```
CSV 24개 구조 검사       파싱 깨짐 0건, 인코딩 문제 0건
행 수 대조               24개 중 22개 일치
작물 분포 대조           crops_초안.csv 와 실데이터 완전 일치
```

**데이터는 건전합니다. 틀린 것은 문서입니다.**

다만 문서가 틀린 방향이 나쁩니다 — 없는 작물을 있다고 적었고, 행 수를 3배로 적었습니다.
이 문서를 믿고 DB 설계를 하면 통째로 어긋납니다.

## 작업 원칙 — 먼저 읽을 것

1. **이 요청서의 주장도 검증하십시오.** 각 항목에 확인 명령을 붙여 두었습니다.
   명령을 돌려 결과가 다르면 **고치지 말고 그 사실을 보고**하십시오.
2. **데이터 파일(CSV)은 ⑥번 외에는 건드리지 마십시오.** 나머지는 전부 마크다운 문서 수정입니다.
3. **`wc -l` 로 CSV 행을 세지 마십시오.** 이 사고의 원인입니다. 반드시 `csv` 모듈로 세십시오.
4. 고친 뒤 **어느 줄을 어떻게 바꿨는지** 목록으로 보고하십시오.

## ② `파일구조.md:162,164` — 행 수가 3배 부풀려짐

**현재**

```
| `품종정보_품종_숙기.csv` | 1,867 | `crop_variants` ★ |
| `품종정보_품종목록.csv` | 1,940 | 품종 이름·코드 |
```

**무엇이 틀렸나**

`주요특성`·`mainChartrInfo` 칸에 줄바꿈이 들어 있어 `wc -l` 로 세면 3배가 됩니다.
CSV 자체는 정상입니다(따옴표 균형 확인함).

```
품종정보_품종_숙기.csv    wc -l 1,867  →  실제 607
품종정보_품종목록.csv     wc -l 1,940  →  실제 607
```

**고칠 내용** — 숫자를 `607` 로 바꾸고, 표 아래에 주석 한 줄을 답니다.

```
⚠ 품종 CSV 두 개는 칸 안에 줄바꿈이 있어 `wc -l` 로 세면 3배가 된다.
   행 수는 반드시 csv 모듈로 셀 것.
```

**확인 명령**

```powershell
python -c "import csv;[print(f,len(list(csv.DictReader(open(f,encoding='utf-8-sig'))))) for f in ['품종정보_품종_숙기.csv','품종정보_품종목록.csv']]"
```

둘 다 `607` 이어야 합니다.

**다른 22개 파일도 같은 방법으로 재검하고, 어긋난 게 더 있으면 함께 고치십시오.**

