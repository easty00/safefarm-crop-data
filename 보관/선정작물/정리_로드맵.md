2026-09-16. **`결과/14작물_확정표.md` 를 정본으로 삼아 실물을 거기에 맞추는 작업 순서다.**

루트의 `safefarm_작물데이터_로드맵.md` 는 프로젝트 전체 할 일이고,
이 문서는 그중 **14작물 데이터를 한 벌로 맞추는 실무**만 다룬다.

```

맞출 것    결과/crops_초안.csv
          결과/crop_variants_초안.csv
          ../재해규칙/결과/disaster_rules.csv
```

## 0. 지금 어긋난 것

문서가 아니라 **실물 CSV 가 확정표를 못 따라왔다.** 구체적으로 다섯 곳이다.

| # | 파일 | 증상 | 확정표 어디 |
|---|---|---|---|
| ① | `crops_초안.csv` | `base_temp` 22행 중 **5행만** 참 (시금치·수박·마늘·감자×2) | B-2 |
| ② | `crops_초안.csv` | `upper_temp` 22행 중 **3행만** 참 (시금치·마늘·양파) | B-2 |
| ③ | `crops_초안.csv` | 벼·수박·상추가 `target_confirmed=Y` — **②단위라 N 이어야 함** | C |
| ④ | `crops_초안.csv` | 상추 `target_sum=1,400~1,700` — **추대 경보값이지 수확 목표가 아님** | C |
| ⑤ | `crop_variants_초안.csv` | **수박 4행뿐.** 벼·감자·양파 3분할과 나머지 MID 가 없음 | D |

③④가 특히 나쁘다. **틀린 값에 `confirmed=Y` 가 붙어 있어서** 그대로 믿고 DB 에 넣으면
"농진청 확인값" 으로 둔갑한다.

## 1. 단계 — 이 순서로

앞 단계가 끝나야 뒤가 의미 있다. 건너뛰면 다시 한다.

### 1단계 · `crops.csv` 를 확정표에 맞춘다 `← 지금 여기`

```
[ ] 1-1  select.py 에 온도표를 상수로 박는다            내가 고침
         확정표 B-2 의 14작물 × (base_temp · upper_temp · confirmed · 출처)
         ⚠ 지금처럼 기준온도후보.csv 에서 자동으로 긁지 않는다.
           그 파일엔 13종밖에 없고, 논문값·근연추정은 사람이 고른 것이라
           자동으로 나올 수 없다. 고른 근거를 코드에 적어 남긴다.

[ ] 1-2  target_sum 정정                              내가 고침
         벼·수박   target_confirmed  Y → N   (②단위. ③으로 역산해야 함)
         상추      target_sum 비움              추대값은 4단계에서 재해규칙으로

[ ] 1-3  select.py 실행                               그쪽이 실행
[ ] 1-4  결과 확인 — base 22/22 · upper 22/22 가 찼는지   그쪽
```

**완료 판정**

```
crops_초안.csv 에서
  base_temp 빈칸 = 0
  upper_temp 빈칸 = 0
  base_confirmed=Y 인 작물 = 시금치·수박·마늘·감자 4종뿐
  target_confirmed=Y 인 행 = 0            ← 역산 전이므로 하나도 없어야 정상
```

### 2단계 · `crop_variants.csv` 를 채운다

확정표 D 대로다. 총 **23행**이 나와야 한다.

```
[ ] 2-1  벼·감자·양파 3분할                            내가 고침
         품종_숙기.csv 의 숙기 분포를 EARLY/MID/LATE 로 접는다
             극조생·조생 → EARLY   중생 → MID   중만생·만생 → LATE
         벼 검산 : EARLY 106 · MID 101 · LATE 164

[ ] 2-2  수박 4분할 유지                               이미 있음. 손대지 않음
         소과 750 · 조생 800 · 중생 1,000 · 만생 1,200
         ⚠ 만생종만 confirmed=N (API 40~45 vs 첨부 45~50 — 확인필요 §1-1)

[ ] 2-3  나머지 10작물 MID 한 행                        내가 고침
         배추·무·상추·시금치·당근·마늘·고추·파·가지·방울토마토
         gdd_target 은 빈칸 (역산 전)
         비고에 0 인 이유를 적는다 — 확정표 D-2 의 네 갈래

[ ] 2-4  실행 · 행 수 확인 (9 + 4 + 10 = 23)            그쪽
```

### 3단계 · 문서를 실물에 맞춘다

**CSV 를 먼저 고치고 문서를 나중에 고친다.** 반대로 하면 또 어긋난다.

```
[ ] 3-1  빈칸.md 재생성                                select.py 가 같이 만듦
[ ] 3-2  확정표에 "CSV 반영 완료" 표시                   내가
[ ] 3-3  파일구조.md 의 채움 상태 갱신                    내가
         "22행 중 5행만 채움" → 실제 숫자로
[ ] 3-4  문서정정_요청서.md 8건 중 남은 것 확인·종결       그쪽 판단
         ①④ 는 이미 반영된 것으로 보임. ③⑥⑦ 은 상태 불명
```

### 4단계 · 재해규칙으로 옮길 것

```
[ ] 4-1  상추 추대 1,400~1,700 → disaster_rules.csv     내가 고침
         crop_id=상추 · disaster=추대 · metric=적산온도 · op=>= · value=1400
         source = "농작업일정 첨부 '상추 농작업일정.hwpx'"
         confirmed = Y   (원문 그대로. 단 ②단위임을 비고에 적는다)

[ ] 4-2  「채소류의 생육 및 장애온도」 표를 rules.py 에     루트 로드맵 A-3 과 같은 일
         호냉성 25 · 호온성 35 · 동해온도 → 12작물 고온·저온 규칙
         ⚠ 이 표의 "최저" 칸은 base_temp 로 쓰지 않는다 (확정표 B)
```

### 5단계 · 기상 일통계가 오면

여기부터는 루트 로드맵 §2-B 와 같다. 이 문서에서는 목록만 남긴다.

```
[ ] 5-1  벼 9조합으로 계산식 검증        ★ 이게 틀리면 아래가 전부 무의미
[ ] 5-2  배추 3작형으로 base_temp 역산    상한 있/없 둘 다 재서 식(2) 채택이 옳은지 확인
[ ] 5-3  11작물 target_sum 역산          → crops.csv · confirmed=N
[ ] 5-4  crop_stages 전 작물             벼는 5단계 없이도 지금 가능
```

## 2. 사용자가 정해야 진행되는 것

값이 갈려서 내가 못 고르는 것들이다. **1·2단계는 이것 없이도 굴러간다** —
확정표에 잠정값을 넣어뒀기 때문이다. 다만 확정되면 그 행만 고치면 된다.

| 항목 | 갈린 값 | 확정표 잠정값 | 어디 |
|---|---|---|---|
| 가지 `base_temp` | 논문 10~11 · MRCC 15.6 · 국내 17 · 더미 12 | **10** | 확인필요 §2-1 |
| 방울토마토 `upper_temp` | 논문 28~33 · 국내표 35 | **30** | 확정표 B-3 |
| 수박 만생종 일수 | 첨부 45~50 · API 40~45 | **47** (첨부) | 확인필요 §1-1 |
| 마늘 처리 | 적산 모델 부적합 | 일단 포함 | 루트 C-2 |
| 배추·파 `base_temp` | 논문에 없음 | **5** (근연·호냉성) | 루트 C-4 |

## 4. 완료 상태는 이렇게 생겼다

```
crops_초안.csv          22행 · base 22/22 · upper 22/22 · target 0/22(역산 전)
crop_variants_초안.csv   23행 · gdd_target 은 수박 4행만 참
disaster_rules.csv      286행 + 상추 추대 1행 + 채소류 장애온도 규칙
빈칸.md                 "기준온도 빈칸 0종 · 목표값 빈칸 11종" 으로 바뀜
14작물_확정표.md          B-2 에 "CSV 반영 2026-09-__" 표시
```

이 상태가 되면 **Safe-farm 으로 넘길 준비가 된 것**이다.
`gdd_target` 은 비어 있지만, 그건 기상 데이터가 없어서지 정리가 덜 된 게 아니다.

## 5. 왜 이 순서인가

```
CSV → 문서 순서       반대로 하면 문서가 또 앞서 나가 어긋난다. 이번 사고가 그것이다
1단계가 먼저          crops 의 base·upper 가 없으면 역산도 stages 도 못 한다
4-1 을 1-2 뒤로       상추 target_sum 을 비우기 전에 옮기면 값이 두 곳에 남는다
5단계를 맨 뒤로        벼 검증(5-1)이 틀리면 11작물 역산이 전부 헛일이다
```

**한 줄로**: 값 → 표 → 문서 → 검증. 지금은 값이 표를 못 따라온 상태다.
