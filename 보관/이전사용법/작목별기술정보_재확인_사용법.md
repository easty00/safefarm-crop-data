# 작목별농업기술정보 재확인 — 사용법

## 이게 뭐 하는 거야?

농사로 **작목별농업기술정보(cropEbook)** 의 본문을 정말 못 받는지 다시 확인하는 프로그램이야
(`ebook_recheck.py`).

## 왜 다시 확인하나

로드맵 §2-5에 이렇게 적혀 있어.

```
❌ cropsEbookFile 다운로드 링크 → "선택한 페이지를 찾을 수 없습니다" HTML 반환 (링크 사망)
→ cropEbook은 "어느 자료의 몇 쪽을 봐야 하는지"까지만 알려주고 숫자는 주지 않는다
```

그런데 **이 결론의 근거는 수박 하나뿐이야.** 표본 1개로 서비스 전체를 접은 상태지.

이게 걸리는 이유는, 여기 들어있는 게 **농업기술길잡이**라서야. 농진청이 작목마다 펴낸
수백 쪽짜리 교과서고, 우리가 찾는 기준온도·생육단계별 온도 조건이 있을 법한 자료야.
진짜로 막혔다면 확실히 접고, 한 건이라도 열리면 파고들 가치가 있어.

**5분이면 끝나.** 작목 20종을 찍어보고 몇 건이 열리는지 세는 거야.

## 무슨 과정으로 돌아가나

```
[1단계] 대분류 → 중분류 → 작목 훑기
        식량작물·채소·과수 … → 과채류·엽채류 … → 수박·배추·고추 …

[2단계] 작목마다 길잡이 목록을 받고, 본문 파일 주소로 실제로 받아보기
        받아온 걸 앞 몇 바이트로 판정:
          %PDF  로 시작  → 진짜 PDF        ✅
          PK    로 시작  → 한글/압축 파일   ✅
          <html 로 시작  → 오류 안내 페이지  ❌
        동시에 목차(cropIndexList)도 나오는지 확인
```

**오류 페이지도 200 OK로 돌아오기 때문에** 상태코드만 봐서는 성공인지 알 수 없어.
그래서 내용 첫 바이트를 보고 가르도록 했어.

## 실행 방법

명령 프롬프트를 열고 프로젝트 폴더로 이동해:

```
cd "C:\Users\lecra\Desktop\safe\api테스트"
```

### 1) 작목 20종으로 확인 (추천)

```
python ebook_recheck.py
```

3~5분. 성공한 파일이 있으면 `받은파일/` 에 저장돼.

### 2) 특정 작목만

```
python ebook_recheck.py --crop 수박
```

로드맵이 실패했다고 적어둔 그 수박을 그대로 재현해보고 싶을 때 써.

### 3) 전체 작목

```
python ebook_recheck.py --all
```

작목이 몇 종인지는 1단계가 끝나야 알아. 20종이 다 실패하면 전체를 돌릴 필요는 없어.

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--limit 20` | 작목 몇 종을 볼지. 기본 20 |
| `--all` | 전체 작목 |
| `--crop 수박` | 이름에 그 글자가 들어간 작목만 |

## 중간에 끊기면?

**그냥 다시 실행하면 돼.** API 응답은 캐시해두니 두 번째부터는 빨라.
다만 **파일 다운로드 시도는 매번 새로 해.** 그게 이 프로그램이 확인하려는 것 자체라
캐시하면 의미가 없거든.

혹시 `알수없음` 판정이 나오면 그 줄의 `비고` 를 같이 알려줘 — 내가 예상 못 한 형식이라
판정 방법을 고쳐야 한다는 뜻이야.

## 문제가 생기면

- `.env 안에서 AGRI_API 를 찾지 못했습니다` → `.env` 파일이 프로젝트 폴더에 있는지 확인
- `resultCode 13` → 오퍼레이션 이름 문제. 매뉴얼(`cropEbook/OpenAPI 활용 매뉴얼 …txt`)에
  적힌 9개 이름만 썼으니 나오면 알려줘
- 목차도 전부 실패로 나오면 → 로드맵이 "목차는 된다"고 적어둔 것과 어긋나는 거라 꼭 알려줘
