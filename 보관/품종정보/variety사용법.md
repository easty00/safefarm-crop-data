# 품종정보 수집 — 사용법

## 이 폴더는 뭐야?

농사로 **품종정보(`varietyInfo`)** 하나만 맡는 폴더야.

```
품종정보/
  variety.py      ← 실행할 프로그램 (이거 하나면 돼)
  사용법.md        ← 지금 읽고 있는 것
  결과/
    raw/          농사로가 보내준 원문
    첨부/          품종요약서 원본 (분류/작물 로 폴더가 갈려)
    본문/          첨부를 글자로 바꾼 txt  ← 내가 읽을 건 여기야
```

`.env` 는 이 폴더에 안 넣었어. 프로그램이 **위쪽 폴더로 올라가면서 찾아** 써.

## 대상은 2,599품종 전체야

**작물을 미리 좁히지 않아.** 여섯 분류를 통째로 받아.

| 분류 | 품종 | 작물 종수 |
|---|---|---|
| 식량작물 (FC) | 1,018 | 24 |
| 화훼 (FL) | 839 | 27 |
| 특용작물 (IC) | 266 | 27 |
| 채소 (VC) | 247 | 23 |
| 과수 (FT) | 221 | 11 |
| 녹비작물 (FG) | 8 | 3 |
| **합계** | **2,599** | **115** |

품종이 0건인 작물은 없어. 115종 전부 뭔가 나와.

품종 수 상위는 논벼 383 · 콩 168 순인데, 화훼가 839건으로 분류 단위로는 두 번째로 커.

## 왜 첨부까지 받나

목록 응답의 `주요특성(mainChartrInfo)` 은 이 정도 분량이야.

```
가. 용도 : 밥쌀용
나. 주요특성 : 중만생, 식미치 양호, 저온발아성 우수, 흰잎마름병(K1~K3) 강
```

**우리에게 필요한 출수기·성숙기 날짜가 여기엔 없어.** 게다가 2,599건 중 **1,672건은
`가. 나. 다.` 구분조차 없는 통글**이라 항목으로 쪼개지지도 않아.

실제 날짜와 생육 일수는 **첨부된 품종요약서(hwpx)** 안에 있어. 그래서 첨부를 받고
전문을 글자로 바꿔.

## ⚠ 용량을 먼저 알고 시작해

표본 30건을 재봤더니 이랬어.

```
중앙값 0.9MB · 평균 3.7MB   (최소 0.3MB, 최대 31.7MB)
2,599건 추정 → 2.4GB ~ 9.6GB
```

편차가 커서 정확히는 몰라. 재해예방정보가 1.6GB였으니 **그보다 2~6배**로 보면 돼.

디스크가 빠듯하면 아래 "나눠서 받기"를 봐.

## 실행 방법

```
cd "C:\Users\lecra\Desktop\safe\api테스트\품종정보"
python variety.py
```

기본이 **2,599건 전부 + 첨부 전부**야. 2~4시간 걸릴 거야.

### 먼저 목록만 (1분)

```
python variety.py --files none
```

이미 한 번 돌려놔서 `raw/` 에 응답이 다 들어있어. 다시 실행하면 API 를 안 부르고
`품종목록.csv`·`특성.csv`·`요약.md` 만 새로 만들어. 순식간에 끝나.

### 나눠서 받기 (디스크가 빠듯하면)

```
python variety.py --cat FC          식량작물 1,018건만
python variety.py --cat VC,FT       채소+과수 468건만
python variety.py --cat FL          화훼 839건 — 우리 서비스와 제일 멀어. 맨 나중에
```

**노지 작물이 목적이면 `FC,VC,FT,IC` 1,752건이 핵심이고 화훼 839건은 후순위야.**
다만 버리자는 게 아니라 **순서**를 말하는 거야. 나중에 `--cat FL` 로 채우면 돼.

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--cat FC,VC` | 분류를 골라서. 쉼표로 여러 개 |
| `--files all` | **기본값.** 첨부 전부 |
| `--files none` | 첨부 안 받음. API 만 |
| `--limit 40` | 앞에서 40건만. 시험용 |

## 이 서비스가 주는 것

오퍼레이션이 5개야. 이 프로그램은 5개를 다 써.

| 오퍼레이션 | 무엇 | 나오는 파일 |
|---|---|---|
| `mainCategoryList` | 분류 6개 | `분류목록.csv` |
| `middleCategoryList` | 작물 115종 | `작물목록.csv` |
| `subCategoryList` | 숙기·지대·기능 코드 | `코드표.csv` |
| **`varietyList`** | **품종 2,599건 · 칸 24개** | **`품종목록.csv`** ★ |
| `insttList` | 기관명 — 검색 조건용이라 안 씀 | — |

두 가지는 함정이 있어서 적어둘게.

**`middleCategoryList` 는 세 가지를 섞어서 줘.** `gubn` 이 `CLASS1`(대분류)·`CROP`(작물)·
`YEAR`(육성년도)로 갈려. 예전에 이걸 안 가르고 육성년도 2016~2025를 작물로 세어서
품종 0건이 나왔던 적이 있어. 지금은 `CROP` 만 골라 써.

**`subCategoryList` 는 `categoryCode` 를 무시해.** `FC`·`VC`·`FC010101` 로 각각 불러봤는데
똑같은 124개가 나와. 그래서 한 번만 불러. 그중 이름이 있는 건 109개고 나머지는 `-` 야.

## 결과물

```
결과/
  요약.md        ★ 이걸 나한테 보여주면 돼
  품종목록.csv    ★ 2,599건 × 응답 24칸 전부 + 이름 붙인 칸
  특성.csv        주요특성을 '가. 용도 : …' 단위로 쪼갠 것
  작물목록.csv    115종
  코드표.csv      숙기·지대·기능 코드 124개
  본문/          품종요약서 전문 txt  ← 여기가 진짜
  첨부/          원본 hwpx
```

### 품종목록.csv

응답 24칸을 **하나도 안 버리고** 다 넣고, 거기에 읽기 쉬운 칸을 더 붙였어.

```
cntntsNo, cntntsSj(품종명), svcCodeNm, mainChartrInfo(주요특성 원문),
unbrngYear(육성년도), unbrngInsttInfo(육성기관),
mtrtSeCode, grdlSeCode, skllSeCode, atchFileLink, imgFileLink, …   ← 응답 원본
분류코드, 분류명, 작물명, 세부작물, 숙기, 지대, 기능, 첨부, 첨부KB, 본문, 본문자수  ← 붙인 것
```

코드는 **이름을 붙이되 원래 코드 칸도 남겨뒀어.** `숙기`·`지대` 는 빈 품종이 꽤 있는데,
그건 농사로가 코드를 안 넣은 거라 우리가 채울 수 없어.

`기능(skllSeCode)` 은 `218044|218046` 처럼 여러 개가 붙어 오길래 풀어서 `|` 로 이어뒀어.

### 특성.csv

`주요특성` 한 덩어리를 항목별로 한 줄씩 쪼갠 거야. 다만 **2,599건 중 927건만 쪼개져.**
나머지 1,672건은 `가. 나.` 구분이 없어서 `(구분없음)` 한 줄로 들어가.

항목 이름이 `용도`·`용 도`·`용    도` 처럼 제각각이라 띄어쓰기를 지워서 맞췄어.
그래도 `수량성`/`수량`, `성숙기`/`성숙` 처럼 갈리는 게 남아있으니 **표로 옮길 땐
`요약.md` 의 항목 목록을 먼저 보고** 묶어야 해.

## 중간에 끊기면?

**그냥 다시 실행하면 돼.** 이미 받은 첨부와 이미 만든 txt 는 건너뛰어.
오류 응답은 저장 안 하게 해뒀어.

## 다 받은 다음에 할 일

`결과/요약.md` 를 보여줘. 내가 볼 건 이 다섯 가지야.

1. **첨부 실패가 몇 건인가** — 맨 아래. 0이 아니면 그 작물을 따로 손봐야 해
2. **판독 건수가 첨부 건수와 같은가** — 다르면 hwpx 아닌 형식이 섞여있다는 뜻
3. **분류별 용량** — 어디가 무거운지 봐야 다음 계획을 세워
4. **주요특성 항목 이름 상위 30** — 표 설계의 재료야
5. **숙기·지대가 채워진 비율** — 낮으면 코드로는 못 걸러내고 본문을 읽어야 해

그 다음엔 내가 `본문/` 에서 작물별로 **출수기·성숙기·생육일수**를 뽑아낼 거야.
적산온도 계산의 시작점과 끝점이 되는 값들이야.

## 문제가 생기면

- `.env 를 찾지 못했습니다` → 위쪽 폴더(`api테스트`)에 `.env` 가 있는지 확인
- `resultCode 13` → 오퍼레이션 이름 문제. 매뉴얼 이름만 썼으니 나오면 알려줘
- `모르는 형식 (앞 4바이트 …)` → 확장자가 아니라 내용으로 판정하는데도 모르는 게 나온 거야
- 디스크가 모자라면 → 중단하고 `--cat` 으로 나눠서 받아. 받은 건 안 지워져

## 참고 — 왜 천천히 받나

요청 사이에 0.4초씩 쉬어. 농사로와 첨부 서버(`atis.rda.go.kr`)는 정부 서버라
몰아서 요청하면 차단될 수 있어. 다른 스크립트들과 같은 간격이야.
