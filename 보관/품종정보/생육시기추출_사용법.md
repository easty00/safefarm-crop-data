# 품종 생육시기 추출 — 사용법

## 이게 뭐야?

`품종정보/결과/첨부/` 에 **이미 받아둔 2,537건**에서 출수기·성숙기·숙기·생육일수를
뽑는 프로그램이야. 로드맵 7단계야.

**새로 받는 건 없어.** 인터넷을 안 쓰고 `.env` 도 필요 없어.

```
품종정보/
  variety.py             (전에 쓴 것 — API 수집)
  variety_stage.py       ← 이번에 실행할 것
  생육시기추출_사용법.md    ← 지금 읽는 것
  결과/
    첨부/ 본문/           ← 읽을 원본 (이미 있음)
    생육시기.csv           ← 새로 생김
    생육일수.csv
    품종_숙기.csv
    생육시기_요약.md
```

## 왜 어려운 일인가 — 형식이 다섯 가지야

첨부 2,537건의 앞 4바이트를 세어보니 이래.

```
hwp (구형식)  1,171   표 구조가 없다. 칸이 한 줄씩 흩어진 평문만 나온다
pdf          1,140   자리를 맞춰 읽으면 칸이 세로로 맞는다
hwpx           209   표가 XML 로 들어 있어 행·열을 그대로 살릴 수 있다
사진            14   글자가 없다
한글 3.0         3   조합형으로 건져낸다
```

**과반이 hwp 라서 표를 격자로 되살릴 수가 없어.** 재해예방정보 때 썼던 방법이 안 통해.

hwp 평문은 이렇게 나와.

```
품 종 명        ← 머리 블록 시작
성숙기
(월.일)         ← 단위 표시. 여기가 머리 블록이라는 증거
경장
(cm)
천립중
(g)
다유            ← 값 블록 시작. 첫 품종 이름
10.15          ← 머리에서 성숙기가 첫 칸이므로 이 값이 성숙기
```

그래서 **머리 블록 다음에 나오는 첫 '날짜만 있는 줄'** 을 값으로 봐.
요약서의 주인공 품종이 표 첫 줄에 오는 규칙을 이용한 거야.

## 신뢰도를 세 단계로 적어

완벽하지 않아서 **어떻게 찾았는지를 같이 남겨.** 숫자만 믿지 말고 원문을 같이 봐.

| 신뢰도 | 어떻게 | 믿을 만한가 |
|---|---|---|
| `표` | hwpx 표 격자에서 머리글과 값을 짝지음 | **가장 확실** |
| `머리블록` | 평문에서 머리 블록 다음 첫 날짜 줄 | 대체로 맞지만 확인 필요 |
| `문장` | "성숙기가 10월 28일로" 처럼 문장 안 | 맥락을 봐야 함 |

한 품종에 같은 항목이 여러 번 나오면 **가장 믿을 만한 것 하나만** 남겨.

### ⚠ 날짜가 아닌 걸 날짜로 읽는 함정

표에는 이런 숫자가 같이 있어.

```
등숙률 92.3    현미 천립중 19.5    쌀수량 543
```

`92.3` 을 그냥 읽으면 92월 3일이 돼. 그래서 **1~12월, 1~31일만 날짜로 봐.**
이걸 안 걸면 등숙률과 천립중이 전부 출수기로 둔갑해.

## 결과물

```
결과/
  생육시기_요약.md   ★ 이걸 나한테 보여주면 돼
  생육시기.csv      ★ 품종 × 항목(출수기·성숙기·개화기·수확기·파종기) × 월 × 일
  생육일수.csv       생육일수·등숙일수·육묘일수
  품종_숙기.csv      2,599품종 전부 + 숙기 + 적응지역
```

### 생육시기.csv

```
분류명, 작물명, 세부작물, cntntsNo, 품종명, 육성년도,
항목, 월, 일, 행, 신뢰도, 원문
```

`cntntsNo` 로 `품종목록.csv` 와 바로 이어져. `행` 은 표에서 몇 번째 줄이었는지야
(1이면 그 요약서의 주인공 품종, 0이면 문장에서 찾은 것).

### 품종_숙기.csv

2,599품종 **전부** 들어있어. 숙기를 못 찾은 것도 빈칸으로 남겨.

```
숙기출처  코드     농사로 응답의 숙기 코드 (가장 확실)
        주요특성  "나. 주요특성 : 중생, 초다수성" 에서 찾음
        본문     품종요약서 글에서 찾음
```

미리 세어보니 **세 군데를 다 뒤지면 54%** 가 나와. 코드만 쓰면 16%야.
논벼는 97%까지 올라가.

## 네가 물어본 숙기 3단계

요약에 **`숙기 × 출수기 (논벼)`** 표를 넣어뒀어. 이런 모양이야.

```
| 숙기 | 품종 수 | 가장 이른 | 중앙 | 가장 늦은 |
```

이게 이번 실행의 진짜 목적이야. **숙기별 출수기가 실제로 갈리는지**를 봐야
3단계로 접어도 되는지 정할 수 있어.

- 구간이 뚜렷이 갈리면 → 3단계(또는 5단계)로 나누는 게 뜻이 있어
- 겹치면 → 나누는 뜻이 없고 품종별로 가거나 다른 기준을 써야 해

숫자를 보고 정하자. 지금은 아직 못 정해.

## 다 돌린 다음에 할 일

`결과/생육시기_요약.md` 를 보여줘. 내가 볼 건 이 다섯 가지야.

1. **숙기 확보율** — 54% 근처면 정상. 출처별 비중도 같이
2. **시기 항목별 신뢰도 분포** — `표` 비중이 높을수록 좋아
3. **작물별 확보율** — 논벼·콩·보리가 높아야 해. 낮으면 읽는 방법을 고쳐야 해
4. **숙기 × 출수기 (논벼)** — 위에 쓴 그 표
5. **판독 실패** — 사진 14건 말고는 0이어야 해

## 문제가 생기면

- `품종목록.csv 가 없습니다` → 먼저 `variety.py` 를 돌려야 해
- 출수기가 거의 안 나오면 → 머리 블록 찾는 규칙이 안 맞는 거야. 요약.md 를 보여줘
- 값이 이상하면(예: 출수기 12.31) → `원문` 칸을 보여줘. 읽는 규칙을 고칠게
- 오래 걸리면 → `--group` 으로 나눠 돌려도 돼. 결과 파일은 그때마다 새로 써
