# 농작업일정 첨부 추출 — 사용법

## 이게 뭐야?

`농작업일정/결과/첨부/` 에 **이미 받아둔 170개**를 글자로 바꾸고 표를 뜯어내는 프로그램이야.

**새로 받는 건 하나도 없어.** 인터넷을 안 써. 그래서 빠르고, `.env` 도 필요 없어.

```
농작업일정/
  farmwork.py           (전에 쓴 것 — API 수집)
  attach.py             ← 이번에 실행할 것
  첨부추출_사용법.md       ← 지금 읽고 있는 것
  결과/

    본문/                ← 새로 생김. 전문 txt
    첨부_*.csv           ← 새로 생김
```

## 왜 이걸 하나

로드맵에서 **가장 큰 미완**이었어. 다른 서비스는 전부 `본문/` 에 풀었는데 농작업일정만
첨부를 받아만 두고 글자로 안 바꿨거든.

그리고 여기 값진 게 들어있어. 고추 한 건만 봐도 이래.

```
생육온도   발아적온 25~32℃ · 모 기르기 적온 22~30℃ · 개화적온 18~23℃
          생육적온 20~30℃ · 과비대적온 18~23℃ · 저장적온 4℃
본문      모 기르기 기간 80~90일 · 개화·열매달림 가능온도 15.5~28.5℃
```

**로드맵 §7 미결에 "고추 과비대 적온 값을 못 구했다"고 적혀 있던 그 값이야.** 18~23℃.

170개를 미리 훑어보니 이만큼 있어.

```
재배적 특성           97건
작형별 출하시기        89건
기상재해 및 생리장해 대책 88건
생육온도 표           77건
생육적온 78 · 발아적온 67 · 모기르기적온 43 · 저장적온 32 · 개화적온 20
```

## 표를 격자로 뜯는다

**글자로만 풀면 못 써.** hwpx 표는 칸마다 줄이 나뉘어서 이렇게 흩어져.

```
생육온도
발아적온
25~32℃
모 기르기 적온
22~30℃
```

어느 값이 어느 항목인지 알 수가 없어. 그래서 **hwpx 안의 표 XML(`hp:tbl`)을 직접 읽어
행·열을 그대로 살려.** 병합된 칸은 차지하는 자리를 같은 값으로 채워서 항목 이름이 아래로
이어지게 했어.

원래 표는 이렇게 생겼어.

```
학명     ¦ Capsicum annuum L. ¦        ¦ 분류          ¦ 가지과
생육온도  ¦ 발아적온            ¦ 25~32℃ ¦ 모 기르기 적온 ¦ 22~30℃
생육온도  ¦ 개화적온            ¦ 18~23℃ ¦ 생육적온       ¦ 20~30℃
생육온도  ¦ 과비대적온           ¦ 18~23℃ ¦ 저장적온       ¦ 4℃
```

### ⚠ 여기서 한 번 틀렸어

**한 행에 이름-값 쌍이 두 개씩** 들어있어. 처음엔 "마지막 칸이 값"이라고 만들었는데,
그러면 `모 기르기 적온 22~30℃` 만 남고 **`발아적온 25~32℃` 가 통째로 사라져.**
고추에서 온도 6개 중 3개를 놓쳤어.

지금은 병합 중복을 지운 뒤 **칸 수가 홀수면 맨 앞이 행 이름**이고 나머지를 둘씩 짝지어.
짝수면 앞에서부터 둘씩. 그래서 6개가 다 나와.

### 표를 두 가지로 다 뽑아둬

표마다 해석이 달라. `작형별 출하시기` 는 이름-값 짝이 아니라 **머리행이 있는 표**야.

```
작형     ¦ 씨뿌림        ¦ 아주심기    ¦ 수확기      ¦ 성출하기
반촉성재배 ¦ 11월 하순~   ¦ 2월 중순~  ¦ 3월 상순~  ¦ 7월 상순~
```

어느 쪽이 맞는지 표마다 다르니까 **둘 다 뽑아뒀어.** `첨부_항목.csv`(짝 보기)와
`첨부_표행.csv`(행 보기). 그리고 `첨부_표.csv` 에 **격자 원본**이 그대로 남아있어서
둘 다 틀려도 되살릴 수 있어.


### 첨부_온도.csv — 이게 핵심

```
분류명, 작물명, cntntsNo, 파일, 출처, 항목, 항목전체, 최저, 최고, 형태, 원문
```

- `출처` 는 `표` 또는 `본문`. 표 쪽이 믿을 만해
- `항목` 은 **띄어쓰기를 지운 이름**이야. `모 기르기 적온`·`모기르기적온` 이 섞여 있어서
- `형태` 는 `범위`(25~32) / `단일`(4℃) / `이상` / `이하`
- **`원문` 을 반드시 같이 봐.** 자동으로 읽은 숫자가 맞는지 확인하는 유일한 방법이야

`cntntsNo` 가 들어있어서 `농작업시기.csv`·`재배법.csv` 와 바로 이을 수 있어.

### ⚠ 이 온도를 `base_temp` 로 쓰면 안 돼

`생육적온 20~30℃` 는 "가장 잘 자라는 온도"지 "이 아래로는 안 자란다"가 아니야.
로드맵 §1 끝에 적어둔 세 가지 구분이 그대로 적용돼.

```
적온     가장 잘 자란다      → 계산에 쓰지 말 것
한계온도  피해가 난다         → disaster_rules.csv
기준온도  생육이 안 진행된다   → crops.base_temp
```

다만 **발아적온의 아래끝**은 기준온도 추정의 단서가 될 수 있어. 그것도 `confirmed=N` 이야.

## 다 돌린 다음에 할 일

`결과/첨부_요약.md` 를 보여줘. 내가 볼 건 이 다섯 가지야.

1. **판독 실패가 몇 건인가** — 170개 중 0이어야 해. 미리 돌려봤을 땐 0이었어
2. **온도를 하나도 못 뽑은 작물이 몇 개인가** — 많으면 표 모양이 다른 계열이 있다는 뜻
3. **온도 항목별 건수와 최저/최고 중앙값** — 작물군마다 값이 말이 되는지 볼게
4. **자주 나오는 표 항목 상위 40** — 온도·일수 말고 **더 캘 게 있는지** 여기서 보여
5. **분류별 표** — 축산·화훼·버섯은 우리 대상이 아닐 수 있어서 비중을 봐야 해

그 다음엔 `첨부_표.csv` 에서 `작형별 출하시기` 와 `기상재해 대책` 을 각각 뽑아
`crop_schedules.csv` 와 `disaster_rules.csv` 로 옮길 거야.

## 참고 — PDF 7건과 hwp 3건

```
"전략작물 가이드북(○○).pdf"  7건   ← 표 격자 없음. 글자만
".hwp" (완두·사과·국화)      3건   ← 표 격자 없음. 글자만
```

표 XML 은 hwpx 에만 있어. 이 10건은 본문 txt 와 본문에서 뽑은 온도만 나와.
PDF 는 쪽 표시(`===== p.12 =====`)가 들어가서 나중에 근거 위치를 댈 수 있어.
