# 보정 — 원본검수에서 나온 구멍을 메운다

`검수/결과/원본검수_2026-09-15.md` 가 지적한 것 중 **코드로 메울 수 있는 것**을 처리합니다.

```
§5   CSV 에 HTML 엔티티 865곳 · hwp 제어코드가 한자로 99건   → 찌꺼기.py
§7   뽑아놓고 결과물로 안 간 값 (수박 숙기별·일수 칸·중복)      → 반영.py
§10  ★★ 온도 추출률 38% — 문장형을 통째로 놓친다             → 온도.py
§11  이 검수도 보지 않은 것 (스캔본·주간농사정보·82작물·참고표)  → ocr.py · 대조.py
```

## 먼저 알아둘 것

- **원본은 건드리지 않습니다.** `raw/` `첨부/` `파일/` 은 어떤 스크립트도 열어보기만 합니다.
- **고치기 전에 백업합니다.** `결과/찌꺼기_백업/` `결과/반영_백업/` 에 원래 파일이 남습니다.
- **모든 스크립트는 인자 없이 돌리면 미리보기입니다.** `--고침` 을 붙여야 실제로 바뀝니다.
  (`ocr.py` 만 예외 — 인자 없이 돌려도 `결과/ocr본문/` 에 새로 만듭니다. 원본 본문은 그대로입니다.)
- **값을 지어내지 않습니다.** 못 정한 것은 `확인필요` 로 남기고 사람에게 넘깁니다.

## 필요한 것

```powershell
python -m pip install pymupdf winocr      # ocr.py 만 필요. 나머지는 표준 라이브러리로 돈다
```

`winocr` 은 Windows 10/11 내장 OCR 을 씁니다. tesseract·torch 설치가 필요 없고 인터넷도
쓰지 않습니다. 한국어 인식기가 있는지는 이렇게 봅니다.

```powershell
[Windows.Media.Ocr.OcrEngine,Windows.Foundation,ContentType=WindowsRuntime] > $null
[Windows.Media.Ocr.OcrEngine]::AvailableRecognizerLanguages | % { $_.LanguageTag }
```

`ko` 가 나와야 합니다. 없으면 Windows 설정 → 시간 및 언어 → 언어에서 한국어 언어 팩을 넣습니다.

## 1. `ocr.py` — 스캔본을 글자로

품종정보 첨부 PDF 1,140개 중 **191개가 글자층이 없는 스캔본**입니다. 사진(JPEG) 14건은
본문 자체가 없습니다. 파싱을 고쳐서 될 일이 아니라 OCR 말고는 방법이 없습니다.

```powershell
python ocr.py                    # 결과/ocr본문/ 에 만든다. 원본 본문은 안 건드린다
python ocr.py --골라 236307       # 파일 경로에 이 말이 든 것만 (시험용)
python ocr.py --반영              # 위 결과를 각 서비스 본문/ 으로 옮긴다
python ocr.py --다시              # 이미 만든 것도 다시
```

- 205건에 약 11분입니다 (쪽당 1~2초).
- **이어받기가 됩니다.** 중간에 끊겨도 다시 돌리면 이미 된 것은 건너뜁니다.
- **실패는 저장하지 않습니다.** 저장하면 다음 실행 때 건너뛰어 영영 모르게 됩니다.
- `--반영` 하면 본문 첫 줄에 `(OCR 로 읽은 글입니다…)` 가 붙습니다. 값을 옮겨 적을 때
  원문에서 온 것인지 OCR 에서 온 것인지 반드시 구분해야 합니다.

### ⚠ OCR 결과를 믿는 법

글자 모양이 비슷하면 틀립니다. 실제로 이렇게 나왔습니다.

```
고관딜    → 고관달       사람 이름
지하시키고  → 저하시키고
```

**숫자는 특히 조심해야 합니다.** OCR 에서 뽑은 값을 `crops` 에 넣을 때는 `confirmed=N`
으로 두고, 쓸 값이면 원본 그림을 눈으로 확인하십시오. 긴 글(육성경위·재배상 유의점)은
믿을 만하고, 숙기(`조생종`·`만생종`) 같은 낱말은 잘 읽힙니다.

`결과/ocr_결과.csv` 에 파일마다 쪽수·글자수·한글비율이 남습니다.
**한글비율이 0.3 아래면 표가 많거나 잘못 읽힌 것**이니 그 파일은 따로 보십시오.

## 2. `찌꺼기.py` — 엔티티·제어코드·마크업 걷어내기

```powershell

python 찌꺼기.py --고침      # 실제로 고친다 (결과/찌꺼기_백업/ 에 원본 보관)
python 찌꺼기.py --낯선      # 목록에 없는 한자 덩어리를 센다. 새 자료를 받은 뒤 볼 것
```

세 가지를 지웁니다.

```
HTML 엔티티      865곳    &#8228; 802 · &#160; 165 …   `주요특성` 칸에 그대로 있었다
hwp 제어코드     23,538곳  漠杳 氠瑢 浴瑣 …             HWP 내부 태그가 가짜 한자로 샌 것
생짜 마크업       4,155곳   <SPAN STYLE="font-size:15pt;">
```

### ⚠ 왜 "소문자로 되돌아가면 지운다" 로 하면 안 되는가

처음에 그 규칙으로 만들었다가 **진짜 한자를 지울 뻔했습니다.**

```
正東 → 63 6B 71 67 → "ckqg"    ← 소문자다. 그런데 주간농사정보의 `정동(正東)에서` 다
作物 → 5C 4F 69 72 → "\Oir"
漠杳 → 6F 20 67 73 → "o gs"    ← 이쪽만 진짜 찌꺼기
```

그래서 **알려진 제어토막 목록**으로만 지웁니다(`찌꺼기토막`). 낯선 한자가 한 토막이라도
섞이면 손대지 않습니다. 남은 것은 눈에 띄지만 지운 것은 영영 모르기 때문입니다.

새 자료를 받으면 `--낯선` 으로 한 번 훑고, `수상함` 표시가 붙은 것이 있으면
`찌꺼기토막` 에 넣은 뒤 다시 돌리십시오.

### 결과

```
95605_대영.txt   91,927자 → 9,560자   한자비율 76% → 0%   (나머지가 전부 마크업이었다)
```

## 3. `온도.py` — 문장형 온도를 잡고 무엇에 쓸지 가른다

**이 폴더에서 가장 중요한 스크립트입니다.**

```powershell
python 온도.py                # 결과/온도_전체.csv · 온도_기준온도후보.csv · 온도_상한후보.csv
python 온도.py --작물 감자      # 한 작물만 원문과 함께
python 온도.py --빠진것         # 기존 첨부_온도.csv 에 없던 것만
```

기존 `농작업일정/attach.py` 는 `이름 : 값` 꼴만 봅니다. 그래서 이런 문장을 통째로 지나칩니다.

```
❍ 씨감자 싹은 5℃ 이상에서 자라기 시작함        ← base_temp 그 자체인데 CSV 에 없었다
❍ 덩이줄기가 굵어지는 데 좋은 온도는 14~18℃
※ 주간 23~24℃, 야간 10~14℃ (27~30℃에서는 비대 정지)
```

정정 요청서 ⑥ 에서 사람이 감자 5℃ 를 손으로 찾아 넣어야 했던 이유가 이것입니다.

**`attach.py` 는 고치지 않습니다.** 옆에서 따로 뽑아 대조표를 만듭니다. 파이프라인을
건드리면 이미 검증된 372행까지 흔들리기 때문입니다.

### 결과

```
본문에서 뽑은 온도   870건   (기존 첨부_온도.csv 372행 → 새로 466건)
감자                0행 → 12행

쓸모별   확인필요 581 · 적온 172 · 무관 54 · 한계온도 40 · 기준온도후보 13 · 상한후보 10
```

### ⚠ `이상` 이 붙었다고 하한이 아니다

이 스크립트를 만들면서 **정반대 뜻으로 분류한 적이 있습니다.**

```
 5℃ 이상에서 자라기 시작      → 하한. base_temp
25℃ 이상에서는 생육 정지      → 상한. upper_temp
```

둘을 같이 묶었더니 마늘·양파·시금치의 **고온 상한 25℃ 가 `base_temp` 후보로** 올라왔습니다.
25℃ 를 base_temp 에 넣으면 적산이 통째로 어긋납니다. 지금은 뒤에 오는 말
(`정지·불량·휴면` vs `자라기 시작`)로 가릅니다.

같은 이유로 이런 것도 걸러냅니다.

```
겨울철 최저온도가 영하 6℃ 이하로 내려가지 않은 지역   → 재배 적지 조건. 한계온도지 기준온도가 아니다
18℃ 이상에서 잎 생육이 촉진                      → `촉진` 은 잘 자란다는 말이지 자라기 시작한다는 말이 아니다
```

### ⚠ 결과는 후보일 뿐이다

`온도_기준온도후보.csv` 13건 중 **6건이 오탐**입니다. 쓸 수 있는 것은 7건뿐입니다.

    쓸 수 있음  감자 5 · 맥주보리 3 · 일반보리 3 · 가지 17
               글라디올러스 8 · 꽃해바라기 10 · 아이리스 5
    오탐       파슬리 25(발아 상한) · 호박 35 ×2(고온 한계) · 들깨 20(적온)
               안개초(값 없음)
    ⚠ 수박 25  같은 문장에 진짜 값 10 이 있는데 25 를 잡았다.
               "생육적온(25~30℃, 생육최저온도 10℃)" — 괄호 안 뒷값이 base 다.
               crops_초안.csv 의 수박 10.0 을 이 파일로 덮어쓰지 말 것.
**원문 칸을 읽고 사람이 정해야 합니다.** CLAUDE.md 가 못 박은 세 가지를 기억하십시오.

```

한계온도  그 아래/위로 가면 피해가 난다       → disaster_rules
```

## 5. `숙기.py` — OCR 로 되살린 글에서 숙기 채우기

`ocr.py` 를 돌린 **뒤에** 씁니다.

```powershell
python 숙기.py               # 결과/숙기_OCR후보.csv 만 만든다 (원본은 안 건드림)
python 숙기.py --작물 양파     # 한 작물만 원문과 함께
python 숙기.py --고침         # 품종_숙기.csv 두 개의 빈칸을 메운다 (백업 남김)
```

스캔본 191건 중 **38건이 14작물**입니다(벼 20 · 양파 9 · 마늘 3 · 상추 2 · 토마토 2 ·
배추 1 · 파 1). OCR 글자를 훑어보니 숙기가 이만큼 되살아납니다.

```
논벼 19/20 · 양파 9/9 · 마늘 2/3        ← 전부 지금은 빈칸이다
```

### ⚠ 먼저 나오는 말을 집으면 틀린다

한 문서에 숙기 말이 여러 번 나오고 **서로 다릅니다.**

```
양파 대관황   "숙기는 조중생으로 히구마와 비슷"          ← 숙기를 직접 말한 문장
             "초형은 직립형이며 생육은 중생종임"         ← 생육 특성 문장
마늘 다산     "만생종이므로 수확시기가 늦어"             ← 이 품종의 숙기
             "재배지역 확대를 위한 조중생종 품종 육성"    ← 앞으로 만들 품종 이야기
```

그래서 문장 꼴에 등급을 매겨 가장 확실한 것만 씁니다(`숙기는 X` · `X종이므로` 가 최상).
`육성`·`보완을 요하는` 같은 말이 든 문장은 아예 뺍니다. **등급이 같은데 값이 갈리면
채우지 않고 `사람이 볼 것` 으로 남깁니다.**

`조중생` 처럼 표준 다섯(극조생·조생·중생·중만생·만생)에 없는 등급은 채우지 않습니다.

### ⚠ 처음 돌렸을 때 걸러낸 두 가지 (2026-09-16)

첫 판에서 12건을 채우려 했는데 **둘이 틀렸습니다.** 지금은 규칙에 막혀 있습니다.

```
자두 퍼플퀸   `대석조생` 을 조생으로 읽음   ← 화분친으로 적힌 **다른 품종 이름**이었다
논벼 조령     `준조생종` 을 조생으로 읽음   ← 준조생은 조생이 아니다
```

그래서 **등급 0(낱말이 그냥 스쳐 지나간 것)은 채우지 않고**, `준`·`조중`·`중조`·`반` 이
앞에 붙은 것은 걸린 등급으로 보아 사람에게 넘깁니다.

표가 섞인 OCR 글에서는 품종 비교표의 **다른 품종 이름**이 숙기처럼 보이는 일이 흔합니다.
화면에 찍히는 `원문` 을 반드시 읽으십시오.

### ⚠ 채운 값은 원문이 아니다

`숙기출처 = OCR본문` 으로 표시하고 `숙기원문` 에 읽은 문장과 파일 경로를 남깁니다.
**이미 값이 있는 칸은 절대 덮지 않습니다.**

## 6. `대조.py` — 아직 아무도 안 본 것을 본다

```powershell
python 대조.py             # 넷 다

python 대조.py --격자       # ④ 표 대조를 행 이름으로 다시
```

### ① 주간농사정보 — 깨끗하다

hwpx 192개를 직접 풀어 저장된 본문과 조각 단위로 맞댔습니다.

```
조각 144,879개 중 본문에서 못 찾은 것 1,601개 (1.11%)
   그림설명 1,592 · 글자만 7 · 숫자있음 2      ← 값 손실은 사실상 없다
회수율 중앙 98.9% · 최소 97.6%
```

## 돌리는 순서

```powershell
cd 보정

python 찌꺼기.py --고침        # 1. 글자부터 씻는다. 다른 스크립트가 이 글을 읽는다
python ocr.py                 # 2. 스캔본 205건 (약 10분)
python 숙기.py                # 3. OCR 에서 숙기 뽑기 — 먼저 후보만 본다
python 숙기.py --고침          #    결과/숙기_OCR후보.csv 의 `원문` 을 읽은 뒤에
python 온도.py                # 4. 온도 다시 뽑기
python 반영.py --고침          # 5. crops_초안 까지 밀어 넣기 (4번 결과를 쓴다)
python 대조.py                # 6. 안 본 것 점검
python ocr.py --반영          # 7. OCR 글을 각 서비스 본문/ 으로 (맨 마지막에)
```

**사람이 봐야 넘어가는 자리가 둘입니다.**

```
3번 → 4번   `숙기_OCR후보.csv` 의 `원문` 칸.      OCR 은 글자를 틀리게 읽는다
4번 → 5번   `온도_기준온도후보.csv` · `온도_상한후보.csv`.  후보에 아직 오탐이 섞여 있다
```

읽지 않고 그냥 넘기면 후보를 그대로 채워 넣습니다.

⚠ **7번을 마지막에 두는 이유** : `--반영` 은 `본문/` 을 OCR 글로 덮습니다. 그 뒤에
`온도.py` 를 돌리면 OCR 오탈자가 온도 값으로 섞여 들어옵니다.
