## 2. 폴더 열한 개

### 2-1. 수집 폴더 다섯 개 — 농사로 API 에서 받아온 것

다 받아놨습니다. **다시 돌릴 일 없습니다.** 합쳐서 7.7GB 입니다.

```
농작업일정/     176건 + 첨부 170        245MB
품종정보/       2,599품종 + 첨부 2,537    3.1GB   ← 가장 큼
재해예방정보/    112건 (2023~2026)        1.6GB
주간농사정보/    목록 870 + 첨부 192      2.6GB
병해충발생정보/   57건                    183MB
```

다섯 폴더가 전부 같은 모양입니다.

```
{폴더}/
  *.py          내려받고 뜯는 프로그램
  사용법.md      돌리는 법
  결과/
    raw/        ★ API 응답 XML 원본. 절대 지우지 마세요
    본문/        HTML/텍스트로 푼 것
    첨부/ 또는 파일/   내려받은 hwp·hwpx·pdf 원본
    *.csv       표로 뽑아낸 것
    요약.md      돌린 결과 보고
    대조.md      원본과 맞대본 기록
```

**`raw/` 와 `첨부/` 가 7.7GB 의 거의 전부입니다.** 이게 있어야 스크립트를 고쳐서
다시 뽑을 수 있습니다. 실제로 이번에 `종료월 13~18` 문제와 HTML 표 문제를 발견했을 때
API 를 다시 부르지 않고 `raw/` 만 다시 읽어서 고쳤습니다.

**⚠ 이 7.7GB 는 git 저장소에 넣지 마세요.**

#### 스크립트가 두 개인 폴더

| 폴더 | 첫째 | 둘째 |
|---|---|---|
| `농작업일정/` | `farmwork.py` API 본문 | `attach.py` 첨부 hwpx |
| `품종정보/` | `variety.py` 품종 목록·특성 | `variety_stage.py` 숙기·생육일수 |

**둘 다 돌려야 합니다.** 첨부 쪽이 API 본문보다 표가 6~7배 많습니다.
가지와 토마토는 **API 표가 0개**라 첨부가 유일한 출처입니다.

## 6. 읽을 때 주의할 것 세 가지

### 6-1. 한계온도 ≠ 기준온도 ≠ 적온

```
한계온도   피해가 난다        →  disaster_rules.csv
기준온도   생육이 안 진행된다   →  crops.base_temp
적온      가장 잘 자란다      →  어느 쪽도 아님
```

**`재해규칙/` 결과는 전부 첫 번째입니다.** 적산온도 계산에 끌어다 쓰면 안 됩니다.

### 6-2. 적산온도는 방식이 세 가지

```
① 단순적산      Σ(일평균)
② 적산온도(관행)  Σ(일평균), 기준온도 이상인 날만 — 빼지 않음
③ 유효적산(GDD)  Σ(일평균 − 기준온도) — 뺌
```

**농진청의 벼 목표값 1,100~1,200℃ 는 ② 단위입니다.** ③ 으로 그대로 쓰면 안 됩니다.
`GDD_작업인계.md` 는 ③ 하나로 가기로 정했으니 목표값 환산이 필요합니다.
