### 방법에 대한 메모 — 정규식 필터로는 안 되는 것

탐사 스크립트가 만드는 `규칙후보.csv`는 `숫자 + 단위 + 비교말`이 한 문장에 있는 것만 뽑습니다.
재해예방정보 3건에서 144문장(중복 제거 65문장)이 나왔습니다.

**이 방식으로는 다음이 전부 빠집니다.**

```
격자표      "10 20 30 60" 같은 숫자 나열 — 한글 비율 필터에 걸려 제외됨
            → 이 보고서의 표 대부분이 여기 해당
정의문      "생육 최저온도는 5℃이다"  — 비교말이 없음
'부터'형    "적산온도 700℃부터 수발아"  — 처음엔 비교말 목록에 없었음(이후 추가)
```

실제로 **가장 값진 자료 3건(벼 한계온도표·가루쌀 적산온도·침관수 감수율표)은 전부 필터에 안 걸렸고,
전문을 읽고서야 나왔습니다.**

→ **정규식은 "이 자료를 팔 가치가 있나"를 가르는 분류 도구로만 쓰고, 값을 캘 때는 전문을 읽어야 합니다.**
`규칙후보.csv`는 참고용이지 완전한 목록이 아닙니다.

### 1-1. farmWorkingPlanNew — 오퍼레이션이 4개가 아니라 5개였다

로드맵 §2-1 표에는 4개만 적혀 있습니다. 활용가이드 `.docx`(2023-11-29 개정)에 다섯 번째가 있고,
샘플소스에는 없어서 그동안 못 찾았습니다.

```
workScheduleGrpList        대분류 10개
workScheduleLst            176건 목록 + 첨부링크
workScheduleDtl            재배법 (HTML)
workScheduleEraInfoLst     월별 달력 (HTML, 36열 = 12개월 × 3순)
workScheduleEraInfoJsonLst ★ 시기 정보 (구조화)   ← 한 번도 안 불렀던 것
```

**실측 결과(5작물 111건):** 순 번호 변환 실패 **0건**, 정보 구분 3종 정상 분리.

```
생육과정(주요농작업)      63건
기상재해 및 예상되는 문제점 44건
병충해 방제               4건
```

HTML 달력은 36칸을 세어야 시기가 나오는데, 이쪽은 `beginMon/beginEra/endMon/endEra`로 바로 줍니다.
HTML 파싱 결과와 대조했더니 들깨 유묘기(6월 상~중, 2순) 등이 **일치**했습니다. 두 방법이 같은 답을
주지만 JSON이 안전합니다.

**주의 2가지**
- `farmWorkFlag`는 작형이 아니라 **작물·작형 통합 명칭**입니다 (`벼 직파재배`/`벼 기계이앙재배`/`들깨`).
  벼의 재배방식 구분에는 쓸 수 있지만, 채소의 촉성·반촉성 구분이 나올지는 176건을 받아봐야 압니다
- `opertNm`에 `<br />` 태그가 섞여 들어옵니다. 저장 전에 지워야 합니다
- 동영상(`vodUrl`) 0건 — 논농사 5건 기준. 다른 카테고리는 미확인

### 1-2. 첨부파일은 두 종류다

176건 전체를 파일명으로 분류했습니다.

```
"○○ 농작업일정.hwpx"          160건   벼 사례: API 상세와 유사도 94.8% (2,858자 vs 3,146자)
"전략작물 가이드북(○○).pdf"      7건   ★ 논농사 전용. 콩·옥수수·참깨·팥·들깨·녹두·사료용벼
"외국인근로자 … 번역본.pdf"       6건   번역본. 작물 데이터 아님
".hwp" (완두·사과·국화)           3건
```

로드맵 §2-1c는 *"첨부 hwpx가 API보다 훨씬 상세하다"*고 단정했는데, 근거가 **가지(채소) 1건**이었습니다.
벼(논농사)는 정반대입니다. 카테고리별로 다를 가능성이 큽니다.

반대로 **전략작물 가이드북 PDF 7건은 API에 없는 내용이 8~10쪽** 들어 있습니다.

2022~2026년 기준 **저온해 65건 · 고온해 31건 · 홍수해 3건 = 99건**입니다.
